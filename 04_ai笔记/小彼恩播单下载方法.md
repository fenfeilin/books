# 小彼恩（Littlebean）云盘播单下载方法

> 把这份说明连同一个播单分享链接交给任意 AI，它就能复现下面的步骤，拿到整个播单的全部音频并下载。
> 仅用于下载页面 / 公开接口本身就返回的资源，不绕过登录、付费或权限。

## 你只需要提供

一个播单里**任意一个音频**的分享链接，形如：

```
https://littlebean.baobaobooks.com/h5/cloudDetail?resource_uuid=<音频UUID>&resource_id=<音频ID>
```

目标：找出这个音频所在的**整个播单**，并把播单里的所有音频下载下来。

## 原理（为什么这样能行）

`cloudDetail` 是个单页应用（SPA），HTML 里没有数据，真实内容由前端 JS 调接口取得。
关键点：每个音频都属于一个目录（播单），detail 接口会返回它的 `dir_id`；
而**按 `dir_id` 列目录下全部资源的接口是公开的**，于是从一个音频就能反查出整张播单。

接口服务前缀（所有接口都挂在这个 base 下）：

```
https://littlebean.baobaobooks.com/xiaobienapi/diandubi/v1
```

所有请求都需要带一个请求头，否则报 `ValidationError: 未传递header参数X-HB-Client-Type`：

```
X-HB-Client-Type: xiaobien-mobile
```

## 步骤一：用单个音频查出它的 dir_id

调音频详情接口（注意路径带 `/h5/`，参数用 detail 链接里的两个值）：

```
GET /h5/disk/dir/resource?resource_id=<音频ID>&resource_uuid=<音频UUID>
```

返回里关注两个字段：

- `dir_id` —— 这个音频所属播单的目录 ID（接下来要用）。
- `resource_url` —— 这个音频的真实 MP3 直链。

## 步骤二：用 dir_id 列出整张播单的全部音频

调目录资源列表接口。**关键坑**：这个接口路径**不带** `/h5/`（带 `/h5/` 会一直报 `ParamError`）：

```
GET /disk/dir/resources?dir_id=<dir_id>
```

返回结构：

```json
{
  "dir_info": { "dir_id": ..., "title": "播单名", "resource_num": 20 },
  "list": [
    {
      "resource_id": ...,
      "resource_uuid": "...",
      "resource_name": "01_xxx",
      "resource_url": "https://oss-audio.xiaobien.com/.../xxx.mp3",
      "resource_size": 1.16,
      "resource_duration": 76
    }
  ]
}
```

`list` 里就是整张播单的全部音频，每条的 `resource_url` 就是可直接下载的 MP3。
`dir_info.title` 是播单名，`resource_num` 是数量（拿来核对是否取全）。

## 步骤三：下载

遍历 `list`，逐个把 `resource_url` 下载下来即可。建议：

- 文件名用 `序号 - resource_name.mp3`，把 `resource_name` 里的 `/` 替换成 `_`。
- 按 `dir_info.title` 建一个子文件夹。
- 已存在且非空的文件跳过，方便中断后重跑补齐。
- OSS 偶尔会慢或返回 0 字节，跑完后**按 `resource_num` 核对文件数量与大小**，对 0 字节 / 缺失的重下一遍。

## 速查（把 `<...>` 换成实际值）

```bash
BASE="https://littlebean.baobaobooks.com/xiaobienapi/diandubi/v1"
H="X-HB-Client-Type: xiaobien-mobile"
UA="Mozilla/5.0"

# 1) 单音频 -> 拿 dir_id
curl -s --compressed "$BASE/h5/disk/dir/resource?resource_id=<音频ID>&resource_uuid=<音频UUID>" -H "$H" -A "$UA"

# 2) dir_id -> 整张播单列表（路径不带 /h5/）
curl -s --compressed "$BASE/disk/dir/resources?dir_id=<dir_id>" -H "$H" -A "$UA"

# 3) 遍历 list[].resource_url 逐个 curl 下载
```

## 排错对照

| 报错 | 原因 | 解决 |
| --- | --- | --- |
| `ValidationError: 未传递header参数X-HB-Client-Type` | 没带请求头 | 加 `X-HB-Client-Type: xiaobien-mobile` |
| `ParamError: 错误信息` | 列表接口路径用了 `/h5/`，或参数名不对 | 列表接口用**不带** `/h5/` 的 `/disk/dir/resources?dir_id=` |
| `NotFound: 请求的资源不存在` | 接口路径写错 | 对照上面的两个准确路径 |
| 下载下来是 0 字节 | OSS 偶发抖动 | 重新下载该文件 |

## 怎么找到接口的（可复现的排查思路）

如果以后接口变了，可以用同样方法重新摸：

1. 打开 detail 页面 HTML，发现是 SPA，提取入口脚本 `app.<hash>.js`。
2. 在 `app.js` 路由表里找到 `/h5/cloudDetail` 对应的懒加载 chunk，下载该 chunk（注意 `curl` 要加 `--compressed`，否则可能拿到空内容）。
3. 在 chunk 里看到详情页调用了 vuex 的 `getCloudDetail`，参数是 `{resource_id, resource_uuid}`。
4. 回 `app.js` 搜 `getCloudDetail`，得到它真正请求的路径 `/h5/disk/dir/resource`，以及列表方法 `getCloudList` 请求的 `/h5/disk/dir/resources`。
5. 找到 axios 实例的 base 构造函数：`baseURL = /{prefix}/{module}/{version}/`，对应 `("diandubi","v1","xiaobienapi")` → `/xiaobienapi/diandubi/v1/`。
6. 实测发现 H5 列表接口（带 `/h5/`）需要分享 token `q`，但同服务**去掉 `/h5/` 的 `/disk/dir/resources?dir_id=` 可直接按目录 ID 列全部资源**，于是从一个音频反查出整张播单。
