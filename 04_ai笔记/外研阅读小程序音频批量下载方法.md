# 外研阅读小程序音频批量下载方法

这份说明给 AI 或自动化助手使用。目标是在用户已授权访问内容的前提下，从外研阅读小程序相关接口中提取音频列表，并批量下载 MP3。不要写入用户真实姓名、系统用户名、私有文件名、聊天记录或本机绝对路径。

## 适用输入

用户可能提供以下任意一种信息：

- 小程序分享链接，例如 `#小程序://.../...`
- 抓包导出的 CSV / HAR / TXT
- 已拦截到的接口 URL，例如 `https://voice.fltrp.com/api/mini/book_directory?id=<GOODS_ID>`
- 已拦截到的音频详情接口，例如 `https://voice.fltrp.com/api/mini/picture_book/audio_detail?goodsId=<GOODS_ID>&unitId=<UNIT_ID>`

如果用户只给小程序分享链接，而当前环境无法直接打开微信小程序或抓包，就让用户补充 Reqable、Charles、mitmproxy 等工具导出的网络记录。不要猜测 ID。如果当前环境已经有微信和抓包工具，且用户明确授权处理该小程序内容，可以只围绕外研阅读接口做最小范围抓包。

## AI 执行原则

- 只下载用户明确要求、且用户有权访问的音频。
- 不尝试绕过登录、付费、加密、DRM 或权限校验。
- 如果接口返回 `401`、`403`、验证码、登录态过期或需要 Cookie，让用户重新抓包或提供合法访问所需的请求信息。
- 下载目录使用当前工作区下的相对目录，例如 `./<GOODS_ID>_mp3`。
- 输出一个 `manifest.csv`，记录序号、标题、时长、文件名和原始音频 URL。
- 下载后检查 MP3 数量、空文件和文件类型。
- 全程信息脱敏：不要在笔记、回复、脚本或清单里写入用户真实姓名、微信聊天内容、系统用户名、本机绝对路径、局域网 IP、Cookie、Token、OpenID、UnionID、Session、Authorization 等敏感信息。

## 从微信小程序抓包获得接口

如果只有 `#小程序://外研阅读/<SHARE_TOKEN>` 这类分享链接，可以用 Reqable 抓包定位 `GOODS_ID`。操作前确认用户已经授权访问该内容，且抓包工具是用户本机已有工具。

1. 打开 Reqable，确认代理正在运行。界面上出现的本机 IP、端口、设备名只用于本地排查，不写入文档或回复。
2. 打开微信里的外研阅读小程序分享卡片。进入书籍页面后，必要时点击一次目录或播放按钮，让小程序请求音频接口。
3. 回到 Reqable，在请求列表中筛选应用为微信，或搜索以下关键词：

```text
voice.fltrp
book_directory
audio_detail
.mp3
vod.unischool
```

4. 优先记录外研阅读接口 URL：

```text
https://voice.fltrp.com/api/mini/book_directory?id=<GOODS_ID>
https://voice.fltrp.com/api/mini/picture_book/audio_detail?goodsId=<GOODS_ID>&unitId=<UNIT_ID>
```

5. 如果只看到 `book_directory?id=<GOODS_ID>`，后续可用标准下载流程请求目录 JSON，并从 `.data.pictureBookDetailList[0].unitId` 取 `UNIT_ID`。
6. 如果已经看到 `.mp3` 请求，可作为音频地址可访问的旁证，但仍以 `audio_detail` 返回的 `audioUrl` 列表生成下载清单。

抓包导出或粘贴给 AI 前，先做脱敏：

- 只保留外研阅读相关请求；删除无关的微信、聊天、登录、埋点、更新检查等请求。
- 保留必要字段：请求方法、URL、状态码、外研阅读接口响应 JSON。不要保留 Cookie、Authorization、Referer、User-Agent、设备标识、请求头全文或响应头全文。
- 把小程序分享短码写成 `#小程序://外研阅读/<SHARE_TOKEN>`，把本机 IP 写成 `<LOCAL_IP>`，把端口写成 `<PORT>`。
- 不粘贴 Reqable 工程文件名、导出文件的本机绝对路径、系统用户名、聊天窗口名称或联系人名称。
- 如果接口响应里出现用户身份字段、手机号、头像、昵称、OpenID、UnionID、会员信息或订单信息，删除这些字段后再继续。

## 从抓包文件定位接口

如果有 CSV / HAR / TXT，先搜索这些关键词：

```bash
rg -n "voice\.fltrp|book_directory|audio_detail|\.mp3|vod\.unischool" "<CAPTURE_FILE>"
```

优先找这两个接口：

```text
https://voice.fltrp.com/api/mini/book_directory?id=<GOODS_ID>
https://voice.fltrp.com/api/mini/picture_book/audio_detail?goodsId=<GOODS_ID>&unitId=<UNIT_ID>
```

如果只有 `book_directory`，先请求它，从返回 JSON 的 `.data.pictureBookDetailList[0].unitId` 取一个 `UNIT_ID`，再调用 `audio_detail`。实际观察中，`audio_detail` 会返回整本书的音频列表，每条通常包含 `index`、`unitEname`、`unitCname`、`duration`、`audioUrl`。

## 标准下载流程

准备变量：

```bash
GOODS_ID="<GOODS_ID>"
OUT_DIR="./fltrp_${GOODS_ID}_mp3"
mkdir -p "$OUT_DIR"
```

如果只有 `book_directory`：

```bash
curl -L -sS "https://voice.fltrp.com/api/mini/book_directory?id=${GOODS_ID}" \
  -o "$OUT_DIR/book_directory.json"

UNIT_ID="$(jq -r '.data.pictureBookDetailList[0].unitId // empty' "$OUT_DIR/book_directory.json")"
test -n "$UNIT_ID"
```

获取音频详情：

```bash
curl -L -sS "https://voice.fltrp.com/api/mini/picture_book/audio_detail?goodsId=${GOODS_ID}&unitId=${UNIT_ID}" \
  -o "$OUT_DIR/audio_detail.json"

jq '.code, (.data | length)' "$OUT_DIR/audio_detail.json"
```

如果接口成功，第一行应为 `0`，第二行是音频条数。

生成清单：

```bash
jq -r '
  def clean:
    gsub("^\\s+|\\s+$"; "")
    | gsub("[^A-Za-z0-9]+"; "_")
    | gsub("^_+|_+$"; "");
  ["index","english_title","chinese_title","duration_ms","filename","audio_url"],
  (
    .data[]
    | (
        (.index | if . < 10 then "0" + tostring else tostring end)
        + "_"
        + ((.unitEname | clean) // .vid)
        + ".mp3"
      ) as $filename
    | [
        .index,
        (.unitEname | gsub("^\\s+|\\s+$"; "")),
        .unitCname,
        .duration,
        $filename,
        .audioUrl
      ]
  )
  | @csv
' "$OUT_DIR/audio_detail.json" > "$OUT_DIR/manifest.csv"
```

生成 `curl` 批量下载配置：

```bash
jq -r --arg out "$OUT_DIR" '
  def clean:
    gsub("^\\s+|\\s+$"; "")
    | gsub("[^A-Za-z0-9]+"; "_")
    | gsub("^_+|_+$"; "");
  .data[]
  | (
      (.index | if . < 10 then "0" + tostring else tostring end)
      + "_"
      + ((.unitEname | clean) // .vid)
      + ".mp3"
    ) as $filename
  | "url = \"" + .audioUrl + "\"\noutput = \"" + $out + "/" + $filename + "\"\n"
' "$OUT_DIR/audio_detail.json" > "$OUT_DIR/curl_download.conf"
```

下载 MP3：

```bash
curl -L --fail --retry 3 --continue-at - --silent --show-error \
  --config "$OUT_DIR/curl_download.conf"
```

如果 `curl` 支持并行下载，也可以使用：

```bash
curl -L --fail --retry 3 --continue-at - --silent --show-error \
  --parallel --parallel-max 6 \
  --config "$OUT_DIR/curl_download.conf"
```

## 完整性检查

检查非空 MP3 数量：

```bash
find "$OUT_DIR" -maxdepth 1 -name '*.mp3' -type f -size +0c | wc -l
```

检查是否有清单中的文件缺失：

```bash
jq -r '
  def clean:
    gsub("^\\s+|\\s+$"; "")
    | gsub("[^A-Za-z0-9]+"; "_")
    | gsub("^_+|_+$"; "");
  .data[]
  | (
      (.index | if . < 10 then "0" + tostring else tostring end)
      + "_"
      + ((.unitEname | clean) // .vid)
      + ".mp3"
    )
' "$OUT_DIR/audio_detail.json" |
while IFS= read -r filename; do
  test -s "$OUT_DIR/$filename" || printf 'MISSING_OR_EMPTY: %s\n' "$filename"
done
```

抽查文件类型：

```bash
find "$OUT_DIR" -maxdepth 1 -name '*.mp3' -type f | sort | sed -n '1p;$p' |
while IFS= read -r file; do
  file "$file"
done
```

检查目录大小：

```bash
du -sh "$OUT_DIR"
```

## 给 AI 的完成回复模板

完成后只需要告诉用户：

```text
已下载完成：<N> 个 MP3。
下载目录：<OUT_DIR>
清单文件：<OUT_DIR>/manifest.csv
已检查：无缺失/空文件。
```

如果失败，明确说明失败在哪一步，例如无法从分享链接获得接口、接口需要登录态、下载中断、或某些文件为空。
