### 正确点

1. 复权价和真实价的核心差异说对了：拆股、分红、送转会让真实价格出现跳变，如果直接用真实价格算收益，会把公司行为误认为暴跌或暴涨。
2. `daily_bar` 表结构已经接近可用，主键、OHLCV、成交额、昨收、涨跌停、停牌、ST、复权因子都覆盖到了。
3. 你能把 `adj_factor` 单独列出来，这个很好。工程上保留复权因子比只存一套复权价更灵活。
4. 当前沪深 300 成分股不能直接回测历史，这个判断对。它会排除历史上被剔除的差样本，导致策略看起来更稳。
5. `get_next_trade_date` 不能 `date + 1` 的原因也抓到了：周末和法定节假日都不是交易日。

### 主要问题

1. 第 1 题还可以更精确：复权价不是“不能交易”，而是“不是市场真实成交价”。它适合算连续收益和历史指标，但不能拿来模拟成交。
2. `close` 的用途写成“生成交易信号”可以，但如果信号用当天收盘价生成，通常只能在下一个可交易时点成交。这里要小心信号时间和成交时间，避免未来函数。
3. `high == limit_up` 只能说明日内碰过涨停，不代表你一定买不进。更关键的是你下单时点的价格、盘口队列和成交假设。日频回测里常见保守规则是：如果开盘一字涨停，则不能买；如果收盘涨停，可以认为收盘买入困难。
4. 沪深 300 的幸存者偏差不只是“暴跌股票被筛掉”，还包括行业权重变化、市值排序变化、成分股定期调整、并购退市和长期表现差导致被剔除。
5. `get_next_trade_date` 应该明确依赖交易日历表，而不是只“避开周末节假日”。实际实现最好查 `trade_calendar` 中 `is_open = true` 的下一条记录。

### 补充解释

今天你已经跨过第一道门了：不是在学一堆名词，而是在设计一套不会骗自己的数据模型。量化系统里，`daily_bar` 不是孤立存在的，它至少要和两张表配合：

## 今日学习内容

量化研究的底座不是策略，而是数据模型。你后面所有因子、回测和组合构建，都会依赖这三类数据。

### 1. `daily_bar`：每天每只股票的行情状态

它回答的问题是：这只股票今天发生了什么？

典型字段：

| 字段 | 用途 |
|---|---|
| trade_date | 交易日 |
| symbol | 股票代码 |
| open/high/low/close | 真实价格 |
| volume/amount | 流动性 |
| pre_close | 涨跌幅基准 |
| limit_up/limit_down | 涨跌停约束 |
| paused | 停牌约束 |
| is_st | 风险警示过滤 |
| adj_factor | 复权计算 |
| turnover_rate | 换手率 |
| list_date 或 listed_days | 新股过滤 |

### 2. `trade_calendar`：市场是否开门

它回答的问题是：今天能不能交易？下一个交易日是哪天？

典型字段：

| 字段 | 用途 |
|---|---|
| calendar_date | 自然日 |
| exchange | 交易所，如 SSE/SZSE |
| is_open | 是否交易日 |
| prev_trade_date | 上一个交易日 |
| next_trade_date | 下一个交易日 |
| is_month_end_trade_day | 是否月末最后一个交易日 |
| is_quarter_end_trade_day | 是否季末最后一个交易日 |

注意：月度调仓不是自然月最后一天，而是“这个月最后一个交易日”。

### 3. `universe_membership`：某天能选哪些股票

它回答的问题是：这只股票在这个日期是否属于我的股票池？

典型字段：

| 字段 | 用途 |
|---|---|
| trade_date | 交易日 |
| symbol | 股票代码 |
| universe | 股票池名称，如 CSI300 |
| is_member | 是否成分股 |
| weight | 指数权重，可选 |
| effective_date | 生效日期 |

如果你用当前沪深 300 成分回测 2020 年，相当于提前知道了 2026 年哪些公司还留在沪深 300 里，这就是未来信息。

### 4. 数据可见性

量化里有一个核心问题：在某个历史日期，你当时到底能看到什么？

例子：

- 2024 年年报的报告期是 2024-12-31，但可能 2025-03-30 才公告。
- 2020 年某股票后来被调出沪深 300，你不能用今天的成分股名单倒推过去。
- 今天收盘价生成的信号，通常不能假设今天收盘前已经成交。

这叫 point-in-time 思维，也就是按历史当时可见信息做研究。

#### 1. 设计 trade_calendar 表（交易日历表）

为了满足多交易所、多维度的查询需求，我们设计如下表结构（包含 6 个核心字段）：

|   |   |   |
|---|---|---|
|字段名 (Field Name)|数据类型|说明 / 用途|
|calendar_date|DATE|**主键**。自然日日期（如 2026-06-01）。|
|exchange|VARCHAR|交易所标识。中国市场通常用 SSE（上交所）或 SZSE（深交所），因为两地假期偶尔会有微调。|
|is_open|INT/BOOL|判定字段。1 代表该天是交易日，0 代表非交易日（周末或节假日）。|
|prev_trade_date|DATE|上一个交易日的日期。方便快速计算跨节假日的收益率，避免复杂的循环查询。|
|next_trade_date|DATE|下一个交易日的日期。用于判断下一次交易决策的执行时间。|
|is_month_end_trade_day|INT/BOOL|是否是当月最后一个交易日。许多机构的月度调仓策略（如指数增强）都以此字段作为触发信号。|

#### 2. 设计 universe_membership 表（沪深 300 历史成分表）

为了完美还原历史，防止“幸存者偏差”，我们需要记录每一只股票在特定日期是否属于该股票池：

|   |   |   |
|---|---|---|
|字段名 (Field Name)|数据类型|说明 / 用途|
|trade_date|DATE|**联合主键 1**。交易日。|
|symbol|VARCHAR|**联合主键 2**。股票代码（如 600519.SH）。|
|universe|VARCHAR|**联合主键 3**。股票池/指数名称（如 CSI300 代表沪深 300）。|
|is_member|INT/BOOL|判定字段。1 表示该股票在该交易日是成分股，0 表示不是。|
|weight|FLOAT|权重字段。记录该股票当天在指数中的权重（如 0.025 代表 2.5%），用于构建指数增强或复制策略。|

注：在工程实践中，为了节省存储空间，有时会采用 in_date（纳入日期）和 out_date（剔除日期）的区间设计。但对于回测引擎来说，**按交易日展开的扁平表（即上述设计）在查询时速度最快、逻辑最不容易出错**。

#### 3. 用自己的话解释 point-in-time (PIT) data

**解释**：  
Point-In-Time（时间点）数据，本质上就是**“历史的真实切片”**。它不仅记录了“发生了什么事”，还精准地记录了“**这件事在历史上的哪一天、哪一分、哪一秒才被外界知道**”。在量化回测中，它能保证你在模拟历史某一天做决策时，绝对不会用到当时还没发生或还没公布的信息。

**典型例子（以财报为例）**：  
假设上市公司 A 的 2025 年年报（报告期截止到 2025-12-31）。

- **非 PIT 数据（常见坑）**：数据库里只有一个字段 report_date = 2025-12-31，对应的净利润是 1 个亿。如果你在 2026 年 1 月 15 日跑回测，系统直接读取了这 1 个亿的净利润。
    
- **真实的历史（PIT 视角）**：虽然这份财务报告记录的是截至 2025 年底的财务状况，但上市公司 A 直到 **2026 年 3 月 28 日**才正式发布年报公告。也就是说，在 2026 年 1 月 15 日那天，全市场的投资者根本不知道它赚了 1 个亿。
    
- **PIT 数据的设计**：表中会有两个关键时间戳——period_end_date（报告期期末：2025-12-31）和 publish_date（实际公布日期：2026-03-28）。在回测系统里，只有当模拟时间推进到 2026-03-28 之后，这笔财务数据才对你的选股模型“可见”。

#### 4. 工程题解答

**问题**：如果一个因子用今天（TT日）的收盘价计算，那么最早应该在什么时候交易？为什么？

**回答**：  
最早应该在 下一个交易日（T+1T+1日）的开盘（Open）进行交易。

**深度原因分析（从量化工程角度）**：

1. **信息获取的时滞性**：  
    今天的收盘价（Close）只有在市场正式收盘时（比如 A 股的 15:00）才真正确定并生成。在此之前，所有的价格都是变动的（只是最新价，而非最终收盘价）。
    
2. **计算与决策时间**：  
    当 15:00 收盘后，数据服务商推送数据、你的数据库接收数据、清洗数据、运行因子计算程序、生成买卖信号，这一系列工程步骤需要时间（可能需要几秒到几分钟不等）。此时，今天的交易通道已经关闭了。
    
3. **规避未来函数（避免逻辑作弊）**：  
    如果你在回测中假设“用 TT日收盘价计算出因子，并在TT日的收盘时以收盘价买入”，这就相当于你**在 15:00 之前，就预知了 15:00 确切的收盘价，并完成了交易**。在实盘中，你无法在收盘价确定后，再穿越回 15:00 之前去下单。
    
4. **唯一的极速边缘情况（集合竞价）**：  
    有些高频或极速交易系统会尝试在TT日收盘前的集合竞价阶段（如 A 股 14:57 - 15:00）进行估算和交易。但即使这样，使用的也只是“预估收盘价”而非“最终收盘价”，且工程复杂度极高、容错率极低。
    

因此，对于绝大多数规范的日级别量化策略：TT日收盘后计算因子 →→ T+1T+1日开盘（或 T+1T+1日内其他时间）进行交易执行**。
