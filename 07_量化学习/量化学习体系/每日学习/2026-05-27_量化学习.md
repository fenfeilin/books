### 正确点

1. 复权价和真实价的核心差异说对了：拆股、分红、送转会让真实价格出现跳变，如果直接用真实价格算收益，会把公司行为误认为暴跌或暴涨。
2. `daily_bar` 表结构已经接近可用，主键、OHLCV、成交额、昨收、涨跌停、停牌、ST、复权因子都覆盖到了。
3. 你能把 `adj_factor` 单独列出来，这个很好。工程上保留复权因子比只存一套复权价更灵活。
4. 当前沪深 300 成分股不能直接回测历史，这个判断对。它会排除历史上被剔除的差样本，导致策略看起来更稳。
5. `get_next_trade_date` 不能 `date + 1` 的原因也抓到了：周末和法定节假日都不是交易日。

### 主要问题

1. 第 1 题还可以更精确：复权价不是“不能交易”，而是“不是市场真实成交价”。它适合算连续收益和历史指标，但不能拿来模拟成交。
2. `close` 的用途写成“生成交易信号”可以，但如果信号用当天收盘价生成，通常只能在下一个可交易时点成交。这里要小心信号时间和成交时间，避免未来函数。
3. `high == limit_up` 只能说明日内碰过涨停，不代表你一定买不进。更关键的是你下单时点的价格、盘口队列和成交假设。日频回测里常见保守规则是：如果开盘一字涨停，则不能买；如果收盘涨停，可以认为收盘买入困难。
4. 沪深 300 的幸存者偏差不只是“暴跌股票被筛掉”，还包括行业权重变化、市值排序变化、成分股定期调整、并购退市和长期表现差导致被剔除。
5. `get_next_trade_date` 应该明确依赖交易日历表，而不是只“避开周末节假日”。实际实现最好查 `trade_calendar` 中 `is_open = true` 的下一条记录。

### 补充解释

今天你已经跨过第一道门了：不是在学一堆名词，而是在设计一套不会骗自己的数据模型。量化系统里，`daily_bar` 不是孤立存在的，它至少要和两张表配合：

1. `trade_calendar`：告诉你哪些日期能交易、上一个/下一个交易日是什么。
2. `universe_membership`：告诉你某一天某只股票是否属于你的股票池，比如是否属于沪深 300。

这样你后面做因子时，才知道“某个信号在当时是否可见、某只股票当时是否可选、下一个成交日是哪天”。

## 今日学习内容

量化研究的底座不是策略，而是数据模型。你后面所有因子、回测和组合构建，都会依赖这三类数据。

### 1. `daily_bar`：每天每只股票的行情状态

它回答的问题是：这只股票今天发生了什么？

典型字段：

| 字段 | 用途 |
|---|---|
| trade_date | 交易日 |
| symbol | 股票代码 |
| open/high/low/close | 真实价格 |
| volume/amount | 流动性 |
| pre_close | 涨跌幅基准 |
| limit_up/limit_down | 涨跌停约束 |
| paused | 停牌约束 |
| is_st | 风险警示过滤 |
| adj_factor | 复权计算 |
| turnover_rate | 换手率 |
| list_date 或 listed_days | 新股过滤 |

### 2. `trade_calendar`：市场是否开门

它回答的问题是：今天能不能交易？下一个交易日是哪天？

典型字段：

| 字段 | 用途 |
|---|---|
| calendar_date | 自然日 |
| exchange | 交易所，如 SSE/SZSE |
| is_open | 是否交易日 |
| prev_trade_date | 上一个交易日 |
| next_trade_date | 下一个交易日 |
| is_month_end_trade_day | 是否月末最后一个交易日 |
| is_quarter_end_trade_day | 是否季末最后一个交易日 |

注意：月度调仓不是自然月最后一天，而是“这个月最后一个交易日”。

### 3. `universe_membership`：某天能选哪些股票

它回答的问题是：这只股票在这个日期是否属于我的股票池？

典型字段：

| 字段 | 用途 |
|---|---|
| trade_date | 交易日 |
| symbol | 股票代码 |
| universe | 股票池名称，如 CSI300 |
| is_member | 是否成分股 |
| weight | 指数权重，可选 |
| effective_date | 生效日期 |

如果你用当前沪深 300 成分回测 2020 年，相当于提前知道了 2026 年哪些公司还留在沪深 300 里，这就是未来信息。

### 4. 数据可见性

量化里有一个核心问题：在某个历史日期，你当时到底能看到什么？

例子：

- 2024 年年报的报告期是 2024-12-31，但可能 2025-03-30 才公告。
- 2020 年某股票后来被调出沪深 300，你不能用今天的成分股名单倒推过去。
- 今天收盘价生成的信号，通常不能假设今天收盘前已经成交。

这叫 point-in-time 思维，也就是按历史当时可见信息做研究。
