### 补充解释

把 Alpha/Beta 放到你当前阶段，可以先这样理解：

- Beta：你承担了某类系统性风险后自然获得的收益暴露。例如你买沪深 300，市场涨你跟着涨，这主要是市场 Beta。
- Alpha：在扣除这些系统性风险暴露后，策略额外产生的收益。比如同样暴露在沪深 300 上，你的选股组合还能稳定多赚，才有可能叫 Alpha。

但实际研究里不能一开始就宣称“我发现 Alpha”。你必须先确认：

1. 数据没有未来函数。
2. 股票池没有幸存者偏差。
3. 回测没有用复权价模拟成交。
4. 策略收益不是简单来自小市值、行业、市场 Beta 或流动性风险。

### 1. 为什么数据层比 Alpha/Beta 更靠前

Alpha/Beta 是收益归因语言，但它依赖正确的输入。如果输入数据有未来函数或股票池偏差，回归和归因会把错误收益当成能力。

典型错误：

- 用当前沪深 300 成分回测历史，策略看起来有 Alpha，其实只是提前筛掉了差公司。
- 用财报期末日而不是公告日，基本面因子看起来有效，其实用了未来信息。
- 用当天收盘价算信号，又假设当天收盘价成交，相当于知道收盘后又回到收盘前交易。

### 2. Alpha/Beta 最小定义

| 概念 | 最小解释 | 量化里怎么用 |
|---|---|---|
| Beta | 对系统性风险的暴露 | 市场涨跌、行业、规模、价值等风格暴露 |
| Alpha | 扣除风险暴露后的额外收益 | 策略真正想证明的部分 |
| Benchmark | 比较基准 | 沪深 300 策略优先对比沪深 300 |
| Excess Return | 超额收益 | 策略收益 - 基准收益 |
| Active Return | 主动收益 | 组合偏离基准带来的收益 |

注意：超额收益不一定是 Alpha。比如你用沪深 300 做基准，但策略实际买了很多小市值股票，跑赢可能来自小市值 Beta，不一定是选股能力。

### 3. 今天必须补齐的工程基础

`trade_calendar` 解决时间轴问题：今天能不能交易，下一个交易日是哪天，月末调仓日是哪天。

`universe_membership` 解决股票池问题：某个历史日期，某只股票当时是不是沪深 300 成分。

`point-in-time data` 解决信息可见性问题：某个历史日期，当时你能看到哪些数据。
